# Shared football simulation

`shared/simulation.js` is the authoritative, renderer-independent match coordinator. The same modules run in the browser for offline play and in Node for multiplayer. They have no browser, network, timer or rendering dependencies. All persistent state is JSON serialisable. The integration contract is in `CONTRACT.md`.

| Module | Responsibility |
| --- | --- |
| `config.js` | Original rosters, attributes, pitch dimensions and formation anchors |
| `math.js` | Shared scalar/vector helpers without match-state dependencies |
| `rules.js` | Pure decisions for attacking direction, clock, offside candidates, challenge contact order, foul/restart awards and keeper handling area |
| `ball.js` | Ball integration, swept boundary intersection, goal/woodwork geometry and reach obstruction queries |
| `shooting.js` | Pure base shot aim and power shared by release and the visual guide; dispersion application |
| `passing.js` | Pure pass receiver/target, charge, lead and velocity preview; dispersion application |
| `goalkeeping.js` | Pure ball forecasts, safe keeper positioning, bounded swept contact and catch/parry decisions |
| `ai.js` | Pure receiver scoring, pressing selection, formation targets and goalkeeper positioning interface |
| `simulation.js` | State creation, action execution, ownership, phase transitions, movement, rule application, stats and events |

The coordinator imports the specialist modules. Specialist queries share direction, ball-geometry and numerical helpers without importing the coordinator, so there are no circular imports. Rule, AI, pass-preview and goalkeeper queries do not mutate state or spend randomness. Ball integration mutates only its supplied ball; keeper forecasts integrate a copy. Public exports `createMatch`, `stepMatch`, `neutralInput`, `attackDirection` and `getMatchClock` remain available from `simulation.js`.

```js
import { createMatch, stepMatch, neutralInput } from './shared/simulation.js';
const match = createMatch({ duration: 360, humans: [true, false] });
stepMatch(match, [neutralInput(), null], 1 / 60);
```

`stepMatch` mutates and returns the state. Call it on a fixed 60 Hz simulation loop and interpolate rendering separately. Invalid/non-positive time steps are ignored; a single step is capped at 50 ms, so callers must maintain their own bounded accumulator. Simulation time is cumulative active seconds. The football clock maps each half to 45 minutes. Dead balls and intermissions stop active time. `attackDirection(state, team)` returns +1 or −1; `getMatchClock(state)` produces the displayed clock.

`null`/missing input invokes AI for that team's selected footballer, even if `options.humans[team]` is true. This supports disconnected-client fallback. An explicit `neutralInput()` gives an idle connected human control. `shoot`, `passHold` and `throughHold` are held actions with release detected inside the simulation. `pass` and `through` remain quick-pass fallback pulses; lofting, standing tackles, sliding tackles and switching are also pulses consumed after a simulation tick. A held-pass release takes precedence over a same-tick fallback pulse, and a capped charge cannot launch a duplicate pass on release. The network protocol validates action booleans, coalesces pulses until the next input flush, and uses sequence acknowledgement to prevent duplicate delivery from repeating an action. Every analogue input is finite-checked, bounded and normalised. Input fields do not grant direct access to position, score, possession or ball velocity.

The team index selects one of two fixed fictional clubs. `config.js` contains the 22 names, unique squad numbers, role codes and attributes on a 0–100 scale. An optional numeric `seed` initialises the small seeded random generator; the generator's current state is included in match state. Seeded repeatability is useful for tests, but network clients never depend on deterministic lockstep.

## Movement and ball

Pace determines maximum speed; acceleration sets the rate of velocity change. Sprint increases speed and drains stamina. Jockey reduces maximum movement speed; with the ball it activates close control with a shorter lead and faster turning. Braking and direction reversals are more responsive than ordinary acceleration. Stamina recovers more quickly while stationary and never disables ordinary movement. Facing turns at a bounded angular speed. Player bodies separate on overlap.

There is exactly one ball and one nullable owner ID. Assisted dribbling uses a bounded, damped velocity correction towards a foot-side point ahead of the owner. Normal, close-control and sprint movement use different lead distances and touch intervals. Touch metadata drives the visible contacting foot; the renderer never determines possession. The ball continues integrating and possession is lost if it moves too far away. The ball has gravity, air damping, ground friction and bounce restitution. Fast shots may deflect off close bodies; receiving a pass changes the sole owner and cushions incoming velocity according to control ability. Ball height remains continuous and gravity settles an airborne receipt onto the turf. A goalkeeper may hold the ball at hand height and must distribute within a bounded interval.

Passes choose a team-mate using direction, distance, forward progress and obstruction. A strong analogue aim excludes receivers behind that aim; if none qualify, the pass travels into the aimed space. Short passes and through balls charge for up to 0.75 seconds, releasing on button-up or automatically at the cap. A quick tap preserves the low-power pass. `passing.js` supplies the same pure intended receiver, target, lead and velocity to the preview and release. More charge favours longer options and adds pace; through-ball forward lead increases from 5 to 13 metres before pitch bounds. Ground-pass launch speed accounts for rolling resistance, with quick-pass target arrival pace of 4.6 m/s for short passes and 6.8 m/s for through balls; charge adds up to 5 or 7 m/s of launch pace respectively. Short passes on human teams limit motion lead for the imminent control switch. Lofted passes retain their quick ballistic arc. Passing ability, body orientation, nearby opponent pressure and sprinting affect seeded dispersion only at release. Charge cancels when possession or selection changes, and a held capped action must be released before charging again. A human's automatic selection change waits until the current kick/tackle animation and held charge finish; an explicit switch cancels a pending automatic switch.

Shots charge for up to 0.95 seconds and release on button-up or at the cap. `shooting.js` supplies the same pure base-aim and power calculation to the intended-target guide and authoritative release. The guide consumes no random numbers and does not change the match. Release applies seeded dispersion affected by shooting ability, distance, nearby pressure, body orientation, angle to goal and movement speed. The displayed target therefore does not guarantee the shot's final path or result. Repeated held input cannot charge a second shot until release; the existing power bar continues to reflect actual charge.

Standing tackles extend a short foot path in the player's facing direction. Sliding tackles commit to an input, movement or facing direction, with a brief decelerating lunge, an extended foot path, recovery and cooldown. Sliding players cannot steer the ongoing challenge or collect the ball as an ordinary dribbler during recovery. The rule helper compares the earliest geometric intersections of the foot path with the low ball and opposing players' ground footprints. Ball-first contact clears the ball; opponent-first contact awards a foul. An empty challenge, a distant opponent or a foot moving away from an existing overlap does not create a contact foul merely because the tackle button was pressed. These are simplified gameplay contact shapes, not exact animated-boot collision physics.

## Team behaviour

Both sides keep a 4–3–3 formation whose anchors shift with the ball, possession and tactical depth. In possession, the holding midfielder offers a return pass, the central midfielders stagger nearby support to form passing triangles, and the wingers retain width. Forward runs respond to the carrier's orientation, movement, action recovery and nearby pressure. Running targets stay just inside the onside line while a team-mate owns the ball; after release, the intended receiver follows the ball's projected path. These targets do not guarantee that a player's actual position is onside. Attacking tactics allow the ball-side fullback to overlap while the other fullback and centre-backs retain defensive cover.

Out of possession, one player chases the ball and a second screens behind that press towards their own goal. Tactical choice changes this covering distance, rather than sending more players directly at the ball. Centre-backs are discouraged from chasing far forward. The remaining defenders and holding midfielder receive distinct, goal-side marking assignments for dangerous opponents or hold their formation anchors. The intended receiver is the sole player assigned to chase a friendly pass, avoiding several team-mates converging on the same receipt.

Receiver scoring considers aim, distance, progress, lane obstruction, receiving space and, for through balls, forward movement. Strong manual aim remains authoritative over the assistance, and offside players are not automatically excluded. Carriers compare a shot, a pass and forward movement. Difficulty changes opponent decision cadence while keeping physical speed limits identical. Receiver scores, pressing roles, marking assignments and movement targets are pure, deterministic queries of the current match state: they neither mutate it nor consume random numbers. The simulation still owns action execution and seeded shot/pass dispersion.

Goalkeepers bisect the goal-post angle at a bounded depth, step out against an uncovered close attacker, and use the live ball's bounce/drag model to forecast an incoming shot's guarding-plane crossing. Slow loose balls and parry rebounds are collected only when a sampled race estimate favours the keeper over nearby opponents. Position targets stay inside the penalty area; a wide attack limits how far the keeper comes out.

Save contact checks only the ball's actual swept segment during the current tick, before boundary awards. It cannot catch a future forecast or teleport the keeper. Reach is finite and ability-scaled: low-ball reach is 0.72–0.95 metres, raised-ball reach 0.80–1.12 metres, and smother reach 0.55–0.67 metres. Height, limited rear reach, obstruction and lawful handling area constrain contact. A deterministic catch/parry decision uses relative ball speed, ability, pressure and reach extension; it has no random catch roll. Harder shots are more likely to exceed the catch threshold and are parried into the safer lateral space. Recovery and cooldown limit repeated contacts, while subsequent rebound pursuit still needs a favourable race. These are simplified gameplay shapes, not full-body physics. Restart placement remains automated and may reposition players while play is stopped.

## Rules and phases

The pitch is 105 × 68 m and the goal mouth is 7.32 × 2.44 m. A swept goal-line plane test checks the ball's complete crossing, including radius, to avoid skipping goals at high speed. Near-post and crossbar impacts bounce back. If a step crosses two boundaries near a corner, the earliest crossing determines the restart. A goal is accepted only in `playing`, preventing repeated scoring across subsequent frames. Last touch awards throw-ins, corners and goal kicks.

Offside candidates are captured at a team-mate's release using the ball, halfway line and second-last opponent. Receiving involvement awards a free kick; merely standing offside does not. The restart carries an `offside` reason code and a readable explanation identifying the receiving player, and the HUD labels the stoppage OFFSIDE. Direct throw-ins, corners and goal kicks are exempt. Passive interference, deflections/deliberate-play interpretations and every official-law exception are outside this prototype. Opponent-first standing or sliding challenge contact awards a direct free kick, or a penalty when the victim is inside the defender's penalty area. Foul restarts identify the offender, victim and challenge type in their reason. Automated restart takers execute after two seconds, so a match cannot wait indefinitely for restart input.

Phases are `kickoff` (1.6 s), `playing`, `restart` (2 s), `goal` (3 s), `halftime` (4 s) and `fulltime`. The second half changes attacking direction and returns players to starting positions. Full-time freezes active time and the ball. Draws stand. Exactly 22 players remain throughout. Cards, advantage, substitutions, injuries, handball, headers, extra time, shoot-outs and full official-law compliance are not implemented.

Goal replays are entirely client-side presentation. `client/replay.js` keeps an immutable four-second history at up to 20 Hz, detects an observed score increase once, and plays up to the last three seconds in no more than 2.6 seconds. Playback fits within the existing goal phase and does not add a simulation phase, pause authority, change the score or consume seeded randomness. The live state continues to be recorded and checked during playback; leaving the goal phase cancels it immediately. Skip returns to current live state, while rematches and tick/score resets clear the old history. Local human actions are neutral during playback, and HUD scores remain live.

`client/practice.js` owns a separate local `createMatch` state for Shooting & aim and Slide tackle timing. It retains all 22 players but parks uninvolved actors away from the drill and places the relevant players and ball for each attempt. Normal `stepMatch` inputs, shot statistics, goal awards and challenge contacts determine results; practice never fabricates a match goal. A private goal contributes to the shooting success counter before the next fresh setup clears that round's score and statistics. Feedback holds the practice state briefly, then resets it; held actions must be released before the next attempt. Restart clears drill counters. Exhibition state, online rooms and global team configuration are untouched, and practice bypasses match results and replay recording.

`event` is the latest `{id,type,text}` record; its monotonically increasing ID lets UI/audio recognise a new event. Goal events additionally include `team`. `stats` stores shots, passes, completed passes, tackles, saves, fouls, offsides and possession seconds. `receiver[team]` exposes intended recipients, `pendingSwitch[team]` stores a delayed selection request, and `targetX`/`targetZ` support debugging. Restarts use `restart.type`, with `restart.reason` and `restart.reasonCode` explaining foul and offside awards. A network disconnect forfeit may attach `result` and set `fulltime` without fabricating a score.

## Verification

Run `node --test tests/simulation.test.js` from the project directory. Twenty-four tests cover roster/state invariants, live/dead clocks, acceleration and stamina, passing types, aimed receiver eligibility, contextual pass accuracy, committed-action switching, shot release/cap and contextual dispersion, manual switching, swept and repeated goals, post impacts, corner crossing order, restart ownership/exemptions, offside involvement, penalty awards, keeper catch/distribution and obstruction, end changes, JSON round-trip, invalid inputs, AI fallback and a full six-minute AI match. The full-match test samples numerical/ownership/player-count invariants every two simulated seconds.

The initial v0.1 seed 1729 completed both halves with all six phases, 21 shots, 153 passes, 15 saves and a 2–3 score at tick 25482. Later gameplay tuning changes these outcomes; see the current verification report for update checks. This is a functional check of progression and football actions, not a claim of competitive balance. Tests execute simulated time faster than real time and do not measure rendering performance or physical controller/mobile behaviour.

Touchline throw-ins use an overhead release at 1.8 m and a dedicated two-arm throw animation, with a 0.65-second planted follow-through. AI chooses an infield teammate 4-26 m away, preferring a short, less pressured option; with no eligible receiver it throws into the field. Human direction/power remains manual. Throw-ins retain pass/completion accounting and direct-restart offside exemption, and emit a throw event instead of a boot-contact pass sound. Corners and goal kicks retain their foot deliveries.

Penalty restarts store `aimGoalZ` and `aimGoalY` in authoritative restart state. Movement axes are screen-relative target motion during a penalty: left/right moves horizontally across the goal (flipped by attack direction), up/down changes height; neutral input retains both. Shot power sets velocity independently of target height. Normal, finesse and chip penalties share the target with the rendered reticle, with airborne drag/gravity compensation. Human input arming, cancellation and release requirements still apply; AI chooses a target and shoots after setup. A small `ball.lastShot.penalty` record retains the camera through the flight, then possession, a new phase, a replay or a 2.5-second timeout returns to normal framing. Saved camera preferences remain unchanged.

The `penalties` practice drill uses the same manual penalty restart and keeper simulation. Only a released shot increments attempts; actual goals increment successes. Saves/misses provide feedback, then a fresh penalty state clears the target and score while retaining session counters. Held actions must be released between rounds. Waiting and full-power charging have no idle reset. Restart clears counters and Exit leaves the isolated session.
